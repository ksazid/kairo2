# VS-03 Agent Reach Provider Spike

Status: **CONDITIONAL PASS — promote as pinned discovery recipe/provider family, never as arbitrary shell access**

Evaluated upstream: `Panniantong/Agent-Reach@93ae1d18c37b707dec053c7c4f9d91cd8ef8943d`
Package version: `1.5.0`
License: MIT
Observed: 2026-08-13
Decision authority: DEC-005

## Key finding

Agent Reach is not a single structured search API. Its pinned `agent_reach.core` explicitly describes the project as an installer, doctor and configuration layer and tells consumers to call the upstream platform tools directly for reading/searching.

That is useful for Kairo as a maintained public-source recipe/capability catalog, but it makes the unsafe integration obvious:

`Hermes -> shell -> arbitrary Agent Reach/upstream command`

is **not allowed**.

## Kairo integration model

Kairo promotes an `AgentReachDiscoveryProvider` family behind `ToolGateway` with these constraints:

1. Kairo owns the provider contract and normalized evidence schema.
2. The provider version records the exact Agent Reach evaluation pin.
3. Source adapters are explicit and allow-listed; they do not accept an arbitrary executable or argument vector from an LLM.
4. Logged-in/browser-session/cookie-backed sources are disabled for the Global Hunter unless separately approved by source policy.
5. Provider output is normalized into Kairo `DiscoveryEvidence` and then `PublicSignal`; upstream output is never authoritative state.
6. Timeout, response-size, URL policy and cancellation are Kairo-owned.
7. Provider disable/replacement changes only routing. Hunter domain logic and PostgreSQL state remain unchanged.

## Initial safe source posture

### Public web reader

The pinned Agent Reach web channel uses Jina Reader and already performs public HTTP(S) URL normalization, a 30-second network timeout, a 5 MiB response cap and high-confidence anti-bot-page detection. Kairo may adapt the pattern for URL fetch evidence, but must apply Kairo's own SSRF/public-host validation and response limits rather than trusting upstream validation as the security boundary.

### RSS / Atom

The pinned RSS channel uses `feedparser` and requires no authenticated user/browser session. RSS is suitable for a bounded Global Hunter source adapter when a curated public feed set exists.

### Public search

The pinned search path expects mcporter + Exa MCP. Kairo must not let an agent construct arbitrary mcporter commands. If this path is enabled, Kairo owns a fixed MCP client/tool binding for only the approved search capability and normalizes the returned URLs/evidence.

### Public GitHub / YouTube

These remain useful evaluation targets from Agent Reach's source catalog. Kairo should prefer source-specific deterministic adapters and official/safer APIs where available. Authentication or write capabilities are not required for Global Hunter and must not be included merely because an upstream CLI supports them.

### Logged-in social sources

Twitter/X search, Reddit, Instagram, Facebook, Xiaohongshu and other paths that require cookies, browser sessions or user credentials are **not promoted for the VS-03 Global Hunter** by this spike. They require explicit source/session policy and platform feasibility later. Their existence in Agent Reach does not authorize Kairo to import browser cookies or expose session material to agents.

## Structured output and provenance

Every source adapter must return Kairo-owned fields:

- title;
- summary/content excerpt where policy permits;
- canonical source URL;
- platform/source type;
- publisher/author where available;
- published time where available;
- retrieval time generated by Kairo;
- provider id;
- provider version / Agent Reach recipe pin;
- optional content hash.

Missing metadata stays missing; Kairo does not fabricate dates, publishers or confidence.

## Timeout / cancellation

Kairo owns the outer timeout. Any subprocess/MCP/HTTP adapter must be cancellable and killed/aborted after the budget expires. A timed-out provider cannot continue into authoritative persistence because normalization/persistence occur only after the provider call has returned successfully.

## Secret isolation

- No browser cookies or social access tokens are placed in model context.
- No arbitrary inherited process environment is passed to a subprocess adapter.
- If a source later needs a credential, the adapter receives only the minimum source-specific secret from server-side secret management.
- Global-public adapters should remain credential-free where practical.

## Removal / fallback

The provider is replaceable. A source can route to an official API, a direct HTTP/RSS adapter, another public search provider or be disabled without changing `DiscoveryService` or Signal/Opportunity persistence.

## Promotion conditions

For VS-03, Agent Reach is considered promoted only after Kairo tests prove:

- no arbitrary shell command surface;
- exact source adapter allow-list;
- public-host validation;
- bounded timeout and response size;
- normalized source URL + retrieval/provider provenance;
- no credential/session fields in tool input/output;
- disable/fallback behavior;
- provider errors produce no fabricated Opportunity.

## Verdict

**CONDITIONAL PASS** as the pinned recipe/capability source for Kairo `DiscoverySourceProvider` adapters.

**FAIL** as a direct unrestricted shell capability for Hermes or another LLM agent.
